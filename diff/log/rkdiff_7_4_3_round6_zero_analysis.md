# 7-4-3 的 7 轮 RKDiff 第 6 轮概率为 0 的分析

## 结论

本次检查确认：`rkdiff.py` 与 `keydiff.py` 中使用的 Splight S-box 不等式和真实 DDT 一致。7-4-3 中 0 到 6 轮概率为 0 的主要原因不是 S-box 不等式错误，而是当前 RKDiff MILP 输出的是一条局部可行的 characteristic；真实随机实验只按外部 `x` 输入/输出差分统计 differential hull。对于 7-4-3 的 upper 路径，0 到 5 轮外部 `x` 差分可以命中，但命中的内部路径并不是 MILP 输出的那条 characteristic。

## S-box 不等式检查

检查方式：

- 穷举 16 个输入差分与 16 个输出差分。
- 对每个 `(a,b)` 穷举 `pr0, pr1, pr2` 的 8 种二进制取值。
- 比较 MILP 不等式可行性与真实 DDT 是否非零。
- 对真实可行转换，比较最小 `pr0+pr1+pr2` 与 `-log2(DDT[a][b]/16)`。

检查结果：

| 项目 | 结果 |
|---|---:|
| 可行性错误 | 0 |
| weight 错误 | 0 |
| DDT 非零计数分布 | count=16 有 1 项；count=4 有 24 项；count=2 有 72 项 |

因此当前 S-box 不等式本身没有问题。

## 7-4-3 upper 路径中的现象

MILP 输出的第 3 轮附近关键差分为：

| 轮 | `x` | `y` | `l` | `RK` | `ak` | `z` |
|---:|---|---|---|---|---|---|
| 3 | `0200000000000000` | `02000000` | `00200000` | `00200000` | `00000000` | `00000000` |

这要求第 3 轮状态 S-box 走 `2 -> 2`，并且第 3 轮使用的 round key 差分也为 `00200000`，使 `l XOR RK = 0`。

但是用真实 Splight 实现做随机实验时，满足外部状态差分 `x_0..x_5` 的样本走的是另一条内部分支：

| 位置 | MILP characteristic | 真实命中的 hull 分支 |
|---|---|---|
| 第 3 轮 `y` | `02000000` | `0E000000` |
| 第 3 轮 `l` | `00200000` | `00E00000` |
| 第 3 轮 `RK` | `00200000` | `00E00000` |
| 第 4 轮 `RK` | `02000000` | `0E000000` |
| 第 4 轮 `ak` | `02000000` | `0E000000` |

也就是说，外部 `x` 差分没有唯一决定内部 S-box 分支。真实命中的 hull 分支仍然可以让外部 `x_0..x_5` 成立，但它不是 MILP 打印出的这条 characteristic。

## 为什么会稳定出现 `C0000000`

在满足外部 `x_0..x_5` 的样本中，密钥调度差分稳定表现为：

| 全局密钥状态 | MILP 输出 | 真实命中的外部前缀样本 |
|---:|---|---|
| `ks_3` | `00020000000000000000000020000000` | `00020000000000000000000020000000` |
| `ks_4` | `00200000000000002000000000020000` | `00E00000000000002000000000020000` |
| `ks_5` | `02000000200000000002000000200000` | `0E000000200000000002000000E00000` |
| `ks_6` | `00000000000200000020000002000000` | `C00000000002000000E000000E000000` |

差异从 `ks_3 -> ks_4` 的 key schedule S-box 开始。输入差分同为 `2`，但：

- MILP characteristic 选择 key S-box 输出差分 `2`。
- 真实命中的外部前缀样本选择 key S-box 输出差分 `E`。

由于 Splight key schedule 中 `new_k0 = SHI^1(S(k0)) XOR k1 XOR C_i`，`C_i` 不影响差分，`2 -> E` 经过后续轮密钥调度迭代后，会在 `ks_6` 的前 32 bit 中产生 `C0000000`。因此 `C0000000` 不是随机噪声，而是另一条内部 key-schedule DDT 分支传播后的确定结果。

## 对概率测试的含义

当前概率测试统计的是：

```text
Pr[ E_K(x) XOR E_{K+DeltaK}(x+DeltaX) = DeltaY ]
```

它只固定输入差分、输出差分和主密钥差分，不固定每轮内部 `y/l/RK/ak/z`。因此它测到的是 differential hull 的概率，而不是某一条 MILP characteristic 的概率。

7-4-3 的 0 到 5 轮外部差分可命中，是因为 hull 中存在另一条内部路径；但这条路径传播到第 6 轮时不再给出 MILP 指定的 `x_6 = 0000000000000000`，所以 0 到 6 轮和 0 到 7 轮测试为 0。

## 建议

1. 保留当前 S-box 不等式，不需要替换。
2. 概率测试与输出统一使用大写十六进制，避免 `A/a` 字符串比较造成误判。
3. 如果目标是验证单条 characteristic，需要增加内部变量一致性测试，至少检查每轮 `y/l/RK/ak/z`。
4. 如果目标是搜索真实非零概率的 RK differential hull，建议在 `rkdiff.py` 输出候选后加入真实实现的候选过滤：当候选路径外部概率为 0 时，对当前外部差分或关键内部分支加 no-good cut 后继续搜索下一条候选。
